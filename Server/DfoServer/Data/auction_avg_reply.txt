# CMD 0x00B7（点击「开始拍卖」）应答
# ============================================================
# 应答 = 2 字节：flag + mode（逆向自回调 0x1126cd0）
#   flag == 0 -> 按 errcode 分派，弹错误提示框（0xd2/0x69/0x72/0x7e/0xce/0x7b/0x89）
#   flag != 0 -> 再读 1 字节 mode：
#                mode==1 -> push 8 / 建 type 8 窗口 / call 0x1458960
#                mode==0 -> push 7 / 建 type 7 窗口 / call 0x2345cb0
#                其它值  -> 无动作
# ★★★ round17 修复：成功应答必须回 mode=0（建 type7 窗口 + call 0x2345cb0）。
#
#   根因（2026-09-03 定案）：客户端上架窗口对象有一个「上架进行中锁」字段 0x20c，
#   发 0x00B7 时置 1（0x232f602），再次点「上架」时先判 `cmp byte[esi+0x20c],0`，
#   锁未清则直接 return 不发请求（0x232f3c6）——这就是「二次上架发不出请求」。
#
#   清锁唯一路径 = 0x00B7 应答 mode=0 -> 浏览回调 0x2345cb0 -> 0x232f610 ->
#   0x232f6ef `mov byte[esi+0x20c],0`。
#   而 mode=1 走的是 type8 成功回调 0x1458960，根本不触发清锁，锁永远残留。
#
#   ⚠ 清锁条件：0x232f610 清锁前会先 `bag->pop()` 再判 `bag->size()>0`，
#   即官方假设「整堆上架」——上架后背包该堆彻底消失才清锁。
#   拆堆（部分上架，背包残留 keepCount）时该条件不满足，锁可能仍残留。
#   ⇒ 先验证「整堆上架」是否恢复；拆堆场景另议。
#

#      精灵气息   10088620 << 8 = 0x99F0AC00 = -1712280576  ← 负数（材料 id 高位 0x99）
#      水晶碎片   10088621 << 8 = 0x99F0AD00 = -1712280320  ← 负数

#
#   排查手法：改这里后无需重启（ReadReplyConfig 每次请求都重读），

# keyprice= 0  >0 时忽略回显，按"希望输入框预填这个价"反算下发值（下发 keyprice/keydiv）
# keydiv  = 256 客户端放大倍数补偿；若实测预填值 == 下发值，把它改成 1
#   实测结论（2026-09-03）：客户端把回显的 key 直接当预填值用（pre-fill == 下发值），
#   旧的 "×256" 其实是 keyoffset=0 把 key 读成 id<<8 造成的假象，并非客户端乘 256。
#   因此 keydiv 必须 = 1，keyprice 直接等于希望预填的价。

# ==================================================================
# ★★ 双应答 —— 价格输入框 disabled 的根因修复（2026-09-02）★★
# ==================================================================
# 逆向结论（本轮全部落实）：客户端 0x112CBB0 收到 CMD 0x00B6 后，
# 按应答第 1 字节 mode 二选一分派，两条路互斥：
#
#   mode = 0
#     -> CreateWindow(7) 拍卖行浏览窗口
#     -> 0x2335f20(key, &v1, &v2)
#          └ 内部：if (IsWindowOpen(0x114)) 取浏览窗口对象
#                    -> 0x23317d0(&v1,&v2)
#                         [obj+0x224] = 1        ← 「价格统计完成」标志
#                         [obj+0x228] = v1(6×int32)
#                         [obj+0x23c] = v2(6×int32)
#     ◇ 这是全客户端【唯一】的价格入库点 ◇
#
#   mode = 1
#     -> CreateWindow(8) 上架窗口
#     -> 0x1456910(key, &v1, &v2)
#          └ 只把 key 交给 0x1456240 填物品名文本，
#            两个价格向量【一次都没被读取】，直接丢弃。
#
# 结论：只发 mode=1 时，[+0x224] 恒为 0
#       ⇒ 「正在统计拍卖行价格……」常驻
#       ⇒ 竞拍价/一口价两个输入框（ctl2 [+0x18c] / ctl3 [+0x194]）永远 disabled
#
# 启用链（供排查对照）：
#   0x145d620(vt[0], vtable 0x32a21fc) -> 0x145c6c0 -> 0x1456710
#     -> ctl2[+0x18c]->vt[3](1) 启用 + SetText(0xeaec, 0x1455900())
#   而 0x1455900 读 [+0x1a4]=key 与 [+0x1e0]=平均价 float，
#   平均价来自全局价格表 —— 也就是 mode=0 播种进去的那份数据。
#
# 修法：一次请求连发两条应答，顺序不能颠倒
#   第 1 条 mode = 0  播种价格（type 7 路径入库）
#   第 2 条 mode = 1  填物品名 + 打开上架窗口（type 8 路径）
# dual = 0 可退回旧的单应答行为。
dual = 1
