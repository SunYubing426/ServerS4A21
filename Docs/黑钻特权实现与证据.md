# 黑钻特权实现与证据

## 范围与证据等级

本说明随 `feature/black-diamond-privileges` 提交，基于 `382fe1a469c65fc0b45ce1a149a0bd4046f2e5b0`，记录 2026-09-06 选择性移植和审查的依据。当前规则见 [黑钻奖励与加百利特权](黑钻奖励与加百利特权.md)。范围为资格显示、疲劳上限与邮件、普通/高级售货机、额外翻牌及加百利会员策略；未引入疲劳药剂、虚弱恢复行为、婚礼、周年售货机或无关经验系统重构。

证据分为三类，不能互相替代：

- **本分支重新验证**：编译、51 组串行 SelfTest、事务回滚、数据库迁移与协议字节断言。
- **历史客户端分析**：2026-09-05 的 `black-diamond-vending-diagnosis-2026-09-05.md`、2026-09-06 的 `vending-empty-display-20260906.md`、`vending-consumable-full-20260906.md`、`black-diamond-vending-ida-evidence.json`，以及既有翻牌资源分析。下文摘录地址、字段和样本；本次未重新进行完整反编译或动态调试。
- **本服策略**：明确标注的概率、倍率和日常奖励规则。资源能证明池和字段，不能据此宣称官方概率或官方完整行为。

原始诊断材料含本机路径和运行数据，不整体收入仓库。本文保留相关结论、证据位置和复现入口，不包含玩家数据库或账号资料。

## 资格：类型 56 与 USERINFO

历史客户端分支 `0x163CF52` 的 case 56 对应字符串 `0x1155B`“黑钻会员”；登录契约处理 `0x14D606D` / `0x14D3F60` 中类型 56 使用相关图标帧 20/19。类型 1 和 17 等属于不同契约，不能仅凭 premium 非空判为黑钻。

USERINFO 消费链为 `0x13E1940` 读取宠物标识、字符串和 alive 字段，`0x13E2CA0` 读取 PCroom flag，`0x13E2DB0` 再读一字节并设置受保护的 `userData+0x2E8`。对应 subtype0 的 64 字节 after-alive 尾 `+1`；名册 subtype2 的 36 字节尾 `+23`，读点为 `0x13E8906`。售货机入口 `0x234A156` 检查解码资格是否等于 1，否则经 `0x234A16F → 0x2304C70` 进入提示路径，后续 UI `0x148F390` 引用字符串 `0x1123C`。

实现由 [PremiumService](../Server/DfoServer/Game/Premium/PremiumService.cs) 判定账号上未到期的 `premium_type=56`；[SqliteSubtype0FieldsRepository](../Server/DfoServer/Game/CharacterData/SqliteSubtype0FieldsRepository.cs) 按角色真实账号加载资格，再由既有 USERINFO builder 投影 0/1。不新增独立权限缓存，也不把角色 ID 当账号 ID。

[BlackDiamondUserInfoSelfTest](../Server/DfoServer/SelfTests/BlackDiamondUserInfoSelfTest.cs) 被 `premium-contract-protocol` 调用，覆盖类型区分、到期、角色归属及字段位置，并覆盖下文 v26→v27 兼容迁移。

## 售货机：池、请求、ACK 与事务

| 机器 | 消耗物品 | PVF 池 | 历史 NPC 线索 |
| --- | --- | --- | --- |
| 普通黑钻机器 1 | 7454，`stackable/event/vendingmachine/pcroomtoken_vendingmachine.stk` | `etc/pcroom.vm` | NPC 80 |
| 高级黑钻机器 3 | 2749933，`stackable/event/vendingmachine/pcroomtoken_high_vendingmachine.stk` | `etc/pcroom4.vm` | NPC 112 |

入口表是 `etc/vendingmachine.lst`，本功能仅接受上述机器及组 1；NPC 81/88 的周年内容不在范围内。

历史请求包体样本为 `01-00-00-00-01-00-00-00-80-00`：小端 `u32 machine=1`、`u32 group=1`、`i16 coinSlot=128`，长度恰为 10 字节。包名使用 [PacketTypesA21](../Server/DfoServer/Network/Core/PacketTypesA21.cs) 的 `USE_VENDING_MACHINE`，此文不另建 opcode 常量表。

ACK 消费入口 `0x11435F0` 的成功布局为：`u8 success=1`、`i16 coinSlot`、`i32 remainingCoin`、`i32 prizeId`、`i32 prizeCount`、两个零值 `i32`、`u16 recordCount`，随后是记录。普通物品记录含 listType 和既有物品 writer 的记录；`0x1143852` 的 `push 65h` 是 101 字节记录证据。既有 writer 方法名中的 84 不能作为实际长度依据。listType 6 则读取 `i32 itemId + i32 count`，契约成功 ACK 测试长度为 34 字节。

消费者在 `0x114369C` 查找原硬币槽，所以成功 ACK 必须先于硬币槽删除/刷新。容量不足使用失败体 `00 04`，其余拒绝为 `00 01`。前者涉及原生 `0xFF` 错误前缀，后者涉及字符串资源 `0xBBA`；资源 ID（例如 `0x2EA`）不是协议错误码。

[VendingMachineService](../Server/DfoServer/Game/Vending/VendingMachineService.cs) 在当前 owned Inventory lease 中复验会员、硬币和有效期，以既有协调器原子扣币、发奖、激活契约及保存库存。容量规划保留准确失败原因，失败全部回滚。发包由 [VendingMachineHandler](../Server/DfoServer/Network/Handlers/VendingMachineHandler.cs) 和 [VendingMachineAckBuilder](../Server/DfoServer/Network/Builders/VendingMachineAckBuilder.cs) 完成。协议没有可靠请求幂等 ID，每个合法重复请求仍是一次新抽奖。

[BlackDiamondVendingSelfTest](../Server/DfoServer/SelfTests/BlackDiamondVendingSelfTest.cs) 使用真实 PVF，检查解析、资格、两台机器、容量失败、事务回滚、契约奖品、ACK 字节及通知顺序。历史实机记录有腾出消耗品空间后普通机器成功的反馈，但不能替代当前提交的客户端验收。

## 疲劳与 150 点邮件

156/188 上限、首次真实消耗跨越 150 发一枚 7454、北京时间 06:00 切日，是当前服务端规则。邮件标题/正文取自 PVF `etc/hardcodetexttag.etc` 相关资源键 `chn_game_server_msg_23/24`；资源文本本身不证明官方阈值。

[DungeonFatigueService](../Server/DfoServer/Game/Dungeon/DungeonFatigueService.cs) 持有角色每日消耗账本规则；同账号角色共享会员资格，各自记账。普通房间首次进入扣 1，重访不重复扣。既有恢复量仅用于读取抵扣，本分支没有接入疲劳药剂使用入口。选人 ACK 的 `+11` 为已用疲劳、`+13` 为上限、`+15` 为辅助值 0，由 [SelectCharacterFatigueAckSelfTest](../Server/DfoServer/SelfTests/SelectCharacterFatigueAckSelfTest.cs) 断言。

[BlackDiamondFatigueCoinService](../Server/DfoServer/Game/Premium/BlackDiamondFatigueCoinService.cs) 将消耗、每日判定标记、邮件和附件放在同一 SQLite 事务；一次事务冻结一个时间，资格到期、上限、切日和幂等键使用同一基准。非会员跨阈值也记录已判定，之后开通不补发。只有实际新增邮件提交成功才通知 `MAILBOX_ALARM`，幂等重放不再次提醒。下行邮件字符串按客户端消费路径使用 UTF-8，上行既有编码保持原约定。

审查补强了 [DungeonMapHandler](../Server/DfoServer/Network/Handlers/Dungeon/DungeonMapHandler.cs) 等待疲劳门锁后的 owner 校验：捕获玩家、账号、角色、run 和房间，在生命周期锁及 run 锁内重新验证后扣除，发包前后再核对归属。旧副本、换角色或换房间的异步请求不能扣当前角色疲劳。

[BlackDiamondFatigueCoinSelfTest](../Server/DfoServer/SelfTests/BlackDiamondFatigueCoinSelfTest.cs) 覆盖阈值、重试、事务失败、幂等提醒、角色隔离、冻结时钟与会员到期边界，并通过暂停真实 handler 的门锁验证失效请求不扣费、不发包。

## 黑钻额外翻牌

当前 PVF `etc/itemdropinfo_clearreward.etc` 的 `[pcroom card blank item]` 为 `50 7454 1`。50 是候选池内相对权重，不能据此算成官方 0.5%。本服先按 **5% 策略**抽硬币，未命中时用同文件 `[drop prob]` 的 `pcroom default` 经共享生成器单次生成额外物品，`mapRate=1`。该 PVF 的测试解析结果为等级 1..200 基础概率 10000、物品类型权重装备 9500 / 时装 500；测试资源没有满足条件的时装候选。死亡惩罚、空候选等仍可导致无物品，禁止循环重抽或保证每次有奖。

CLEAR 在 paidCardCost 后有两组额外数组，每组八个座位，每座 `u8 count + count*(u32 itemId,u32 count)`。`0x115DBA1` 先读 itemId 再读 count，经 `0x115DBD9` 调用 `0x25F8DC0(itemId,count,seat,2)`，数量写 record+0x30。黑钻使用第二组 kind2。

有实际奖励时，本地座位写两项 `(0,0)`、`(itemId,count)`：`0x25F4798` 将第 0 项数量按金币资源 `0x1DC` 渲染，`0x25F412A` 在元素数不大于 1 时跳过物品，否则从第二项取物品。单写 `(itemId,1)` 会变成显示 1 金币且没有物品；占位 `(0,0)` 只服务客户端布局，不作为实际奖励入账。无奖励写 count=0。

资源绑定链为 `0x25F970F` 常量 `0x322B2A0`，经 `0x27BACC0 / 0x27BAB90 / 0x27BA5A0` 还原到 `interface/newResult/pcroompremiumreward.img`，`0x25F9751` 绑定 `obj+0x50`。kind2 使用 frame1，原始资源文字为“黑钻奖励”。活动 `0x1D` 仅控制附加叠标，不据此把整个控件认作活动牌。

[BlackDiamondCardRules](../Server/DfoServer/Game/Dungeon/BlackDiamondCardRules.cs) 与 [CardRewardService](../Server/DfoServer/Game/Dungeon/CardRewardService.cs) 冻结同一结果供封包和领取使用。额外奖进入既有免费牌持久化副作用及背包事务，付费领取不能再次领取；旧 JSON 缺 extra 字段视为空，不在恢复时重抽。独立副本奖励流程维持原限制。

[BlackDiamondCardCoinSelfTest](../Server/DfoServer/SelfTests/BlackDiamondCardCoinSelfTest.cs) 覆盖真实资源、概率边界、免费领取、重发冻结、持久化恢复和两项布局。以上 UI 结论来自历史资源/静态分析，本次没有运行客户端翻牌验收。

## 加百利会员策略

资源来源为 `etc/secretshop.etc` 普通池，单价和实际候选保持 PVF 值。cash 池归属未证实，不挂到黑钻；`CashUserStackableCount=200` 也不作为本功能商品库存。

[SecretShopMemberPolicy](../Server/DfoServer/Game/SecretShop/SecretShopMemberPolicy.cs) 实现本服策略：原抽取未出现时会员再抽一次，出现率由 p 变为 `1-(1-p)^2`；种类目标和库存各乘 2；实际装备 rarity 2/3 的正权重乘 2，零权重保持零，单位价格不变。这些倍率不是官方逆向结论。真实入场人数为 1..4，参与者各自拥有冻结 offer；同局重开不再叠倍。

[SecretShopPurchaseService](../Server/DfoServer/Game/SecretShop/SecretShopPurchaseService.cs) 为多件非堆叠装备创建独立 core，使用现有背包事务原子扣费与发奖，成功才减少 offer 库存。ACK 保持单槽格式，所有受影响槽通过既有刷新路径通知。审查补上购买前在同一 lease 锁内保存既有 dirty 状态，防止本次失败回滚丢掉更早获得的未保存奖励。

[BlackDiamondSecretShopSelfTest](../Server/DfoServer/SelfTests/BlackDiamondSecretShopSelfTest.cs) 覆盖权重、冻结、库存隔离、真实资源、多装备、第二件失败回滚及重登保存，包含失败购买必须保留此前待保存金币的回归。

## 数据库兼容边界

基础体系仍为 `86jp-database-v1`。目标代码原为 schema 26，来源运行库已经是 27；此次连续迁移仅补入 `stamina_recover_end_unix` 兼容列，并同步 [item_schema.sql](../Server/DfoServer/Sqlite/item_schema.sql) 与 [SqliteMigrations](../Server/DfoServer/Sqlite/SqliteMigrations.cs)。这不是从 18 跨多个业务版本升级，旧开发规范标题滞后；本分支没有引入该列对应的虚弱恢复行为。

迁移测试构造 v26 的缺列/已有列两种数据库，通过真实 `SqliteMigrations.Apply` 连续执行两次，确认版本及 metadata 到 27、缺列默认 0、已有值保留且重复执行幂等。测试不通过修改启动用数据库制造结果。

## 可复现验证与审查结论

2026-09-06 最终结果：**Rebuild 0 warning / 0 error；51 组 SelfTest 全部通过（total=51 pass=51 fail=0）**。这是测试组数量，不是断言数量。聚焦执行过 `premium-contract-protocol`、`black-diamond-vending`、`black-diamond-fatigue-coin`、`black-diamond-secret-shop`、`black-diamond-card-coin`、`select-character-fatigue-ack`，随后串行全量回归；最后的事务和迁移补强又经过聚焦及全量验证。
