# 黑钻奖励与加百利特权

协议与资源依据、实现映射及验证结果见 [黑钻特权实现与证据](黑钻特权实现与证据.md)。

## 资格与既有行为

会员资格复用 `PremiumService`：账号 `account_premiums` 的有效 `premium_type=56`。类型 1、17 和过期 56 不授予黑钻资格；USERINFO 的资格字节仍为 0/1。普通/会员疲劳上限保持 156/188，通关经验奖励按本服既有 10% 保留，标识和售货机使用已有实现。

`SqliteSubtype0FieldsRepository` 根据角色真实账号归属加载资格；subtype0 的 after-alive 尾 `+1` 和选人名册 subtype2 尾 `+23` 写资格 0/1，不改变其他字段。资格在重载时重新判定，不建立另一份角色权限或新增到期推送计时器。

## 疲劳上限与登录显示

`DungeonFatigueService` 使用角色每日账本；同账号角色共享黑钻资格，各自记录消耗。普通副本首次访问每个房间消耗 1 点，重复 START_MAP 不重复扣除。塔、大会和血祭坛不套用普通房间疲劳规则；入场检查覆盖队伍成员，疲劳写入失败时不把房间标记为已消费。

登录 ACK 同步真实已用疲劳和 156/188 上限；过图由既有 `FATIGUE` 通知同步。读取已有数据库时保留 `dungeon_fatigue_recovered` 的抵扣语义，真实消耗计数保持只增不减。疲劳药剂使用入口属于独立功能，不在此分支接入。

## 普通与高级黑钻售货机

`USE_VENDING_MACHINE` 只接入机器 1、3 和当前 PVF 的组 1。奖池、消耗硬币和权重来自 `etc/vendingmachine.lst` 引用的 `.vm` 文件，保留全部有效条目，不重抽、不改掉落权重，也不引入周年机器。

抽奖在当前 owned Inventory lease 内复验账号资格、硬币和过期状态；扣币、统一发奖、契约激活及库存保存使用同一事务。失败回滚，不通过另发邮件补偿。成功时先发抽奖 ACK，再更新硬币及奖品槽；契约奖励另发既有 `CERA_SPECIALITEM` / `PREMIUM_SERVICE`。

真实容量不足走原生失败 ACK `00 04`，其他拒绝使用 `00 01`。容量错误依赖统一发奖规划保留的准确失败原因，不以硬编码公告替代。当前客户端容量提示带“错误”前缀，失败后的结果窗口可能超时进入空展示；这些已知客户端表现仍需实机检查，此分支未修改客户端。

怪物掉落的普通/高级硬币继续走既有 `WorldDropSystem`，拾取不要求会员；抽奖时另行检查会员。每个合法请求独立扣币发奖，请求没有可靠幂等 ID，不宣称网络重试只会执行一次。

## 消耗 150 疲劳的邮件

每个角色在北京时间 06:00 切分的游戏日首次真实消耗跨越 150 时判定一次。当时有效会员由系统邮件发 7454×1；非会员记录已判定，之后开通不补发。疲劳、判定标记、邮件和附件在同一 SQLite 事务提交，失败则全部回滚，房间不标记已消费，可重试。

一次事务冻结同一时间基准，供会员到期判定、疲劳上限、疲劳账本、每日标记和邮件幂等键使用。邮件标题、正文从当前 PVF 的 `chn_game_server_msg_23/24` 读取。`HardcodedTextTagCatalog` 的名称来自 PVF 文件名，不是自拟提示文本；资源缺失时不编造替代文案。

异步房间请求等待疲劳门锁后，必须在玩家生命周期锁和 run 锁内重新验证玩家、账号、角色及房间归属；已失效请求不扣费，发包前后继续核对归属。

邮件模块返回幂等重放状态。只在实际新增邮件提交后发送既有 `MAILBOX_ALARM`；普通消费、重访和重复发放不触发告警。疲劳模块不得查询邮箱内部表来推断是否新建邮件。

## 黑钻翻牌硬币与额外物品

仅在普通通关已有翻牌流程允许时，根据通关时的有效会员资格冻结一次额外奖励。塔、血祭坛、异界等独立奖励流程不套用普通黑钻额外牌策略。无会员或不允许的副本 CLEAR kind2 仍为空。

合资格时先按本服 5% 抽钻石硬币，这是本服规则，不宣称官方精确概率，也不得改成每局必出硬币。命中后按当前 PVF `etc/itemdropinfo_clearreward.etc` 的 `[pcroom card blank item]` 正权重选取奖励及数量；当前为 `50 7454 1`。50 仅作为池内相对权重，不能将其解释成已验证的 0.5%。

未中硬币时，用同一文件 `[drop prob]` 的 `pcroom default` 剖面，经既有 `ClearRewardGenerator` 物品类型、等级、稀有度和装备池单次生成一份真实额外物品。这是本服黑钻额外物品政策：资源数值源于当前 PVF，不声称官方精确规则。`mapRate` 固定为 1，额外独立牌不套用原免费探索倍率；剖面基础概率、副本难度加成和死亡惩罚仍按该生成器计算。禁止循环重抽、禁止复制原免费牌、禁止编造固定赠品。空候选或出现判定未中则 kind2 全 0，不能为撑 UI 绕过校验。本功能未同时扩展 `pcroom bonus` / `pcroom event` 或其他活动牌。

A21 CLEAR 在 paidCardCost 后含两组额外奖励数组，每组为八个座位的 `u8 count + count*(u32 itemId, u32 count)`。CLEAR 读循环 `115DBA1` 先 itemId 再 count，经 `115DBD9` 调用 `25F8DC0(itemId,count,seat,2)`，`25F8ED9` 把 count 写入 record+30。黑钻使用第二组（客户端 kind2）。无奖励或非会员写 count=0，不发空条目制造额外牌。有真实额外物品时本地座 0 写 count=2：第一项 `(0,0)` 金币槽、第二项 `(itemId,stack)`。这与普通免费/付费牌先写 `(0,gold)` 再写物品的位置布局相同；`(0,0)` 只占渲染金币槽，不是实际发放 0 金币，也不进入 persistent extra。渲染 `25F4000` 的 vector 元素 68 字节；`25F478B` 从 kind2 vector+210 取 index0，`25F4798` 读 record+30 无条件按字符串 1DC 画金币；`25F412A` `cmp count,1 / jbe` 跳过物品，物品取第二项 `esi+44` ID。只写一条 `(itemId,1)` 时客户端会把 1 画成金币且不画物品。客户端 `25EF6B0` 要求 kind2 vector 非空才画黑钻牌。第一组、原免费座位列表、付费费用和原生 SELECT_CARD 类型保持原有布局。

客户端资源证据：初始化 `25F970F` 加载常量 `322B2A0`，经 `27BACC0/27BAB90/27BA5A0` 只读还原为 `interface/newResult/pcroompremiumreward.img`，`25F9751` 赋给 `obj+50`；kind2 使用该控件 frame1，原始图像文字为“黑钻奖励”。活动 0x1D 只控制另外的活动叠标，不能据此将整张牌归类为活动奖励。

额外奖励必须进入已有免费翻牌的持久化副作用、背包事务和恢复链路。装备等物品走既有 `InventoryRewardGrantService` 按模板创建默认耐久与槽位，不另加发奖接口或 schema。通关重发、领取重试、持久化恢复不得重抽或重复发物品，付费领取不得领取这份奖励。发包投影与实际发放使用同一冻结结果。旧免费 payload JSON 缺 extra 字段时视为空 extra，不重抽。

## 加百利

以下倍率是本服会员策略，不冒充官方精确概率。商品及单位价格继续从原 PVF 普通池读取，不将尚未证实归属的 cash 池或加百利契约功能直接挂到黑钻。

- 通关生成当前参与者 `DungeonRun.SecretShopOffer` 时判定会员；同局重开商店复用 offer，不重抽或叠倍，各参与者库存隔离。
- 原 NPC 抽取未出现商人时，会员再按同一 PVF 分布抽一次；基础出现概率 p 变为 `1-(1-p)^2`。原配置禁止出现的副本仍不出现。人数使用实际入场队伍人数 1..4。
- 商品种类目标为原 `SelectionCount×2`，按物品 ID 去重，上限为实际正权重候选数；库存为原 `Count×2`，单价不变。
- 只对原候选中的真实装备 rarity 2/3 提高抽取权重至两倍，零权重仍为零。不修改成品稀有度，不编造原池没有的装备。
- 多件非堆叠装备分别创建独立 core；购买、费用、全部物品在原背包协调器内原子提交，任何一件失败均回滚，offer 库存只在成功后减少。
- 开始购买事务前在同一 lease 锁内保存此前已有的 dirty 状态；本次失败回滚不得丢弃更早获得的未保存奖励。
- 购买 ACK 保持原生单槽格式，全部授予槽与材料扣费槽通过既有背包刷新通知投影，不能只刷新最后一件。

## 回归与证据规则

自动化覆盖会员资格、概率边界、零权重、PVF 解析、同局冻结、参与者隔离、事务回滚、重试、重放、通知槽与原协议布局。完整自测串行执行；客户端牌面、动画、邮箱提醒和商店窗口仍由实机验收。

检查 UI 时须追踪“包字段→消费者→控件绑定→原始资源”；相邻顺序、类名和活动叠标只能作为线索，不能替代证据。禁止为通过自测向生产代码添加测试物品/地图 ID 特判或绕过资源校验。
